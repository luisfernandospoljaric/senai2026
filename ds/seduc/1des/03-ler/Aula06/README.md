# Resumo: Metodologias Ágeis, Scrum e Kanban

## Metodologias Ágeis

As metodologias ágeis são abordagens de gerenciamento de projetos e desenvolvimento de produtos que priorizam a entrega contínua de valor, a colaboração entre equipes e a capacidade de adaptação às mudanças.

Diferentemente dos modelos tradicionais, que seguem um planejamento rígido do início ao fim, as metodologias ágeis trabalham com ciclos curtos de desenvolvimento, permitindo ajustes frequentes conforme as necessidades do cliente e do projeto.

### Princípios das Metodologias Ágeis

- Entrega frequente de produtos funcionais.
- Colaboração constante com o cliente.
- Adaptação rápida às mudanças.
- Comunicação eficiente entre os membros da equipe.
- Foco na melhoria contínua.
- Valorização das pessoas e interações.

### Benefícios

- Maior flexibilidade.
- Redução de riscos.
- Entregas mais rápidas.
- Maior satisfação do cliente.
- Melhor controle do andamento do projeto.

# Scrum

O Scrum é um framework ágil utilizado para gerenciar e desenvolver projetos de forma iterativa e incremental. O trabalho é dividido em períodos curtos chamados **Sprints**, que normalmente duram entre 1 e 4 semanas.

Ao final de cada Sprint, uma parte funcional do produto deve ser entregue.

## Papéis do Scrum

### Product Owner (PO)

Responsável por representar os interesses do cliente e definir as prioridades do projeto.

### Scrum Master

Facilitador da equipe, responsável por garantir que o Scrum seja seguido corretamente e remover impedimentos.

### Time de Desenvolvimento

Profissionais responsáveis pela construção do produto.

## Principais Artefatos

### Product Backlog

Lista de todas as funcionalidades, melhorias e correções desejadas para o produto.

### Sprint Backlog

Conjunto de tarefas selecionadas do Product Backlog para serem desenvolvidas durante uma Sprint.

### Incremento

Resultado produzido ao final de uma Sprint.

## Cerimônias do Scrum

### Sprint Planning

Reunião para planejar o trabalho da Sprint.

### Daily Scrum

Reunião diária curta (geralmente 15 minutos) para acompanhamento das atividades.

### Sprint Review

Apresentação do que foi desenvolvido durante a Sprint.

### Sprint Retrospective

Reunião para identificar melhorias no processo de trabalho.

## Vantagens do Scrum

- Organização do trabalho.
- Maior previsibilidade.
- Entregas constantes.
- Transparência no andamento do projeto.
- Facilidade para lidar com mudanças.

# Kanban

Kanban é uma metodologia visual de gerenciamento de tarefas que busca melhorar o fluxo de trabalho e aumentar a produtividade da equipe.

Seu principal objetivo é visualizar as atividades em andamento, identificar gargalos e otimizar a entrega de valor.

## Como Funciona

As tarefas são organizadas em um quadro dividido em colunas que representam os estágios do trabalho.

### Exemplo

| A Fazer | Em Andamento | Concluído |
|----------|----------|----------|
| Criar tela de login | Desenvolver API | Cadastro finalizado |
| Ajustar layout | Corrigir bugs | Relatório entregue |

Cada tarefa é representada por um cartão que se move entre as colunas conforme seu progresso.

## Princípios do Kanban

### Visualizar o Trabalho

Permite que todos acompanhem facilmente o andamento das atividades.

### Limitar Trabalho em Progresso (WIP)

Define um número máximo de tarefas que podem estar em andamento simultaneamente.

### Gerenciar o Fluxo

Busca melhorar continuamente a velocidade e eficiência do processo.

### Melhorar Continuamente

Promove ajustes constantes para aumentar a produtividade.

## Benefícios do Kanban

- Fácil implementação.
- Controle visual das atividades.
- Identificação rápida de gargalos.
- Maior produtividade.
- Flexibilidade para mudanças.

---

# Diferença entre Scrum e Kanban

| Scrum | Kanban |
|---------|---------|
| Trabalha com Sprints | Fluxo contínuo |
| Possui papéis definidos | Não exige papéis específicos |
| Possui cerimônias obrigatórias | Não possui cerimônias obrigatórias |
| Planejamento por Sprint | Planejamento contínuo |
| Mudanças geralmente ocorrem na próxima Sprint | Mudanças podem ocorrer a qualquer momento |
| Indicado para projetos com entregas planejadas | Indicado para manutenção e fluxo contínuo |

---

# Conclusão

As metodologias ágeis ajudam equipes a desenvolver produtos de forma mais rápida, colaborativa e adaptável. Entre elas, o **Scrum** é ideal para projetos que exigem planejamento em ciclos de entrega, enquanto o **Kanban** é mais adequado para equipes que trabalham com fluxo contínuo de tarefas.

Muitas organizações utilizam uma combinação das duas abordagens para obter maior eficiência e flexibilidade no gerenciamento de projetos.
